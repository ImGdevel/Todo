오버레이 와이어프레임 (흑백)

색을 쓰지 않고 형태만으로 그렸습니다. 원칙 ⑤에 따라 상태는 색 없이도 구별되어야 하므로, 여기서 구별되지 않으면 색을 입혀도 실패입니다. 모든 오버레이는 실제 픽셀 크기(1:1)입니다. 글자 크기는 v0.1 사용 기록(125%로 키움)을 반영해 본문 15–16px, 타이머 42px로 잡았습니다.

밀도 3단계 × 상태 5개

큰 단계는 작은 단계에 줄을 덧붙이기만 합니다. 할 일 이름과 시간의 위치는 단계가 바뀌어도 그대로입니다 (Apple 라이브 액티비티 방식, references.md).

고정 모드 ↔ 조작 모드

평소에는 조작 버튼 없이 고정 상태. 마우스를 올리거나 단축키를 누르면 조작 모드로 바뀌고 버튼이 나타납니다 (Xbox Game Bar 방식). 버튼이 늘 떠 있지 않으니 고정 상태는 순수하게 읽기 전용 화면이 됩니다.

폭에 따른 자동 밀도

오버레이 폭이 줄면 위계의 역순으로 요소를 뺍니다. 노트북(S2)처럼 좁게 두면 저절로 최소 단계가 됩니다.

시나리오별 동작

S1 · 듀얼 모니터 코딩

기본
  • 사용자가 둔 위치에 고정, 모니터 구성별로 기억
  • 창 닫기 버튼과 겹치지 않게 기본 위치는 제목 표시줄 아래(위에서 48px)
  • 클릭해도 편집기 포커스 유지 (v0.2 검증)

S2 · 노트북 한 대, 밝은 문서

최소
  • 좁은 폭 → 자동으로 최소(한 줄)
  • 자체 판이 있어 밝은 배경에서도 대비 유지

S3 · 강의 전체 화면 시청

오버레이 비켜남
  • 전체 화면 앱 감지 → 숨김 (설정에서 "최소로 표시"로 바꿀 수 있음)
  • 트레이 아이콘에 비켜남 표시, 단축키 한 번으로 다시 띄움
  • 집중 타이머는 계속 돌고, 끝나면 알림만

S4 · 화상 회의 화면 공유

내 화면
상대가 보는 화면
  • "공유·녹화에서 숨기기"를 켜면 내 화면에만 보임
  • 할 일 내용이 회의에 노출되지 않음

S5 · 게임

오버레이 비켜남
  • S3와 같은 규칙. 집중 세션이 없으면 알림도 없음
  • Discord·NVIDIA 오버레이와 겹치지 않도록 화면 모서리를 비워 둘 필요는 없음 (숨김이므로)

S6 · 아침 계획, 저녁 회고

메인 창
  • 오버레이 범위 밖. 메인 창 재구성 단계(10절 5단계)에서 다룸
  • 오버레이를 누르면 메인 창의 해당 할 일로 이동 (watchOS 컴플리케이션 방식)

발견 1. 대기 상태에 판이 없다 — v2 반영. 점선 테두리만 있고 판이 투명해서, 복잡한 바탕화면이나 밝은 문서 위에서는 글자가 배경과 섞입니다. 전략 4.1절의 "배경에 기대지 않는 자체 판"과 모순입니다. → 대기도 판은 두고, 점선 테두리와 흐린 글자로만 구별.
발견 1-2. 최소 단계의 대기 시간이 너무 강하다 — v2 반영. 최소 단계에서 대기의 50:00이 집중 중의 18:42와 같은 굵기·색이라, 타이머가 도는 것처럼 읽힙니다. → 대기에서는 시간을 흐리게 하거나 시간 대신 "50분 계획"처럼 단위를 붙인 글로.
발견 4. 일시정지 빗금이 글자를 방해한다 — v2 반영. 빗금이 판 전체에 깔려 작은 글자("일시정지", 진행량) 뒤에서 노이즈가 됩니다. → 빗금은 왼쪽 가장자리 띠나 테두리에만.
발견 2. 펼침 단계는 정보 덩어리가 8개를 넘어 1초 안에 읽히지 않습니다. 펼침은 흘끗 보는 화면이 아니라 "멈춰서 보는 화면"으로 정의하고, 조작 모드에서만 열리게 하는 것이 원칙 ②와 맞습니다.
발견 3. 초과 상태의 반전 판은 가장 눈에 띄지만, 초과는 실패가 아니라는 원칙 ⑥과 부딪힐 수 있습니다. 반전 대신 시간 앞 "+" 와 굵은 테두리만으로 충분한지 색 단계에서 다시 비교. 어두운 테마에서는 반전 판이 화면 전체에서 가장 밝은 덩어리가 되어 주변 시야를 끌어당깁니다 (원칙 ① 방해하지 않는다와도 충돌).
