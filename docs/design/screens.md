# 화면 목록과 우선순위

`strategy.md`의 시나리오(S1–S6)와 v0.2 코드(`src/renderer/`)에서 뽑았다. 우선순위는 **얼마나 자주 × 한 번에 얼마나 오래 × 잘못됐을 때 얼마나 아픈가**로 매긴다. 실제 사용 로그가 쌓이면 다시 매긴다.

| 화면 | 언제 | 빈도 | 한 번에 | 하는 일 | 우선 |
|---|---|---|---|---|---|
| **메인 · 오늘** | 아침 계획, 중간 수정, 저녁 정리 (S6) | 하루 3–5회 | 1–5분 | 오늘 할 일 확인·추가·정렬, 체크·진행량, 집중 시작, 일정 확인 | **1** |
| **오버레이** | 일하는 내내 (S1–S5) | 하루 수십–수백 번 흘끗 | 1초 | 지금 할 일·남은 시간·진행량 읽기, 가끔 체크·+1·일시정지 | **1** |
| 빠른 입력 | 작업 중 떠오른 일 | 하루 몇 번 | 2초 | 한 줄 입력 | 2 |
| 할 일 편집 대화상자 | 할 일·루틴 만들 때 | 하루 몇 번 | 30초 | 목표량·단위·일정·반복·서브 할 일·목표 연결 | 2 |
| 메인 · 목표 | 주 시작, 월 시작 | 주 1–2회 | 5분 | 월·주·일 목표 세우기, 진행률 보기 | 3 |
| 메인 · 기록 | 저녁 회고, 주말 | 주 몇 번 | 2–5분 | 날짜별 완료·진행량·계획 대비 실제·초과 | 3 |
| 메인 · 할 일·루틴 | 루틴 손볼 때 | 주 1회 | 2분 | 루틴·남은 할 일 전체 보기 | 4 |
| 목표 편집 대화상자 | 목표 만들 때 | 주 1–2회 | 30초 | 기간·목표량·상위 목표 | 4 |
| 설정 | 처음, 가끔 | 드묾 | 1분 | 오버레이·타이머·알림·단축키 | 5 |
| 트레이 메뉴 | 열기·숨기기·종료 | 하루 몇 번 | 1초 | OS 메뉴 (디자인 범위 밖) | — |

## 1순위 두 화면의 관계

메인 '오늘'과 오버레이는 같은 데이터(오늘 할 일, 지금 할 일, 타이머)를 다른 거리에서 본다. 그래서 **같이 디자인한다**: 할 일 행, 진행량 표현, 시간 표기, 상태 표시가 두 화면에서 같은 모양이어야 한다 (전략 8절 일관성 기준).

- 메인 '오늘' = 가까이서, 앉아서, 손으로 조작 → 밀도 있는 목록, 편집이 쉬워야 함
- 오버레이 = 멀리서, 곁눈으로, 거의 손대지 않음 → 하나만, 크게, 조용하게

# 3순위 화면: 목표 · 기록 · 설정 (v0.3)

작성 2026-11-25. 세 화면 모두 '오늘'과 같은 문법을 쓴다: 사이드바 + 본문 목록 + 오른쪽 열, 구분선 없는 목록, 회색 메타 한 줄, 큰 숫자는 `--font-num` + tabular-nums, 카드는 `.card`(모서리 16 + 키라인). 강조색(Cyan)은 세 화면 어디에도 쓰지 않는다 — 이 화면들에는 "집중 시간이 흐르는 중"인 요소가 없다 (원칙 ⑤).

절마다 순서는 같다: 지금 모습의 문제 → 1초 안에 답해야 할 질문 → 자체 설계 → 레퍼런스 → 같은 기준으로 비교 → 결정.

## 목표

**지금 문제 (v0.3 스타일만 입힌 v0.2 구조)**

| 문제 | 원인 |
|---|---|
| 상하위 관계가 안 보인다 | 월·주·일 탭마다 그 기간 목표만 보인다. 상위는 카드 안 작은 글자 한 줄(`상위 · …`), 하위 목표는 다른 탭에 있다 |
| 카드 격자가 '오늘'의 목록 문법과 다르다 | 목표 1–3개를 300px 카드로 깔아 화면 대부분이 빈칸, 카드 안 구분선·종류 라벨·모드 설명이 겹친다 |
| 같은 설명이 카드마다 반복된다 | "하위 진행량 합산", "하위 목표나 할 일을 연결하면 자동으로 계산됨" |
| 편집이 모달이다 | '오늘'은 오른쪽 패널에서 바로 저장하는데 목표만 대화상자 + 저장 버튼 |

**1초 질문:** 이번 기간 목표들은 각각 얼마나 왔나? 이 목표는 무엇의 일부이고 무엇으로 채워지나?

**자체 설계 (리서치 전):** 기간 탭은 "어느 단계에서 보나"를 고르는 것으로 바꾸고, 본문은 개요(outline) 목록으로 그린다. 고른 기간의 목표가 1단계 행, 그 아래 들여쓴 하위 목표, 그 아래 연결된 할 일. 위쪽 맥락(상위 목표)은 목록을 상위 목표별로 묶는 묶음 제목으로 보여준다. 행 = 제목 + 회색 메타 한 줄(하위 n개 · 합산 방식) + 오른쪽 숫자(`29 / 140쪽`)와 회색 막대. 행을 누르면 오른쪽 열이 목표 편집 패널이 되고, 아무것도 고르지 않았을 때는 기간 요약(목표 수, 기간 남은 날, 평균 진행)을 보여준다. 목표량 없는 수동 목표는 할 일과 같은 원형 체크로 달성 표시.

**레퍼런스**

| 출처 | 본 것 |
|---|---|
| Asana Goals [도움말](https://help.asana.com/s/article/progress-status-and-connecting-work-to-goals) · [포럼: 하위 목표 최상위 숨김](https://forum.asana.com/t/show-goals-and-subgoals-on-goals-page/121321.md) | 목표 설정에서 상위 목표를 고르면 진행이 자동으로 올라간다(하위 목표·프로젝트·할 일 / 수동). 목록에서 같은 팀의 하위 목표를 최상위에서 숨기고 상위 아래로 모았다 — 상하위를 따로 나열하면 중복으로 읽힌다는 반응 |
| Things 3 (`references-visual.md`) | 영역 → 프로젝트 → 할 일을 들여쓰기·여백으로만 구분, 구분선 없음 |
| Linear (`references-visual.md`) | 행 오른쪽에 작은 진행 표시와 숫자, 상세는 옆 패널 |

**비교**

| 기준 | 자체 설계 (기간별 개요 + 상위 묶음) | Asana식 (상위 아래에 하위를 펼쳐 접기) |
|---|---|---|
| 정확성 (상하위가 보이나) | 위(묶음 제목)·아래(들여쓰기) 둘 다 한 화면 | 아래만 보임, 위는 상세로 들어가야 |
| 단순함 | 행 모양 하나, 들여쓰기 두 단계 | 펼침 상태를 기억해야 함 |
| 유지보수 | `goalChildren`·`goalProgress` 그대로 | 펼침 상태 저장 필요 |
| 이 프로젝트에 맞나 | 목표가 기간당 1–5개라 다 펼쳐도 짧다 | 목표 수십 개인 팀 도구용 |

**결정:** 자체 설계를 쓰고 Asana의 "하위는 상위 아래에만 한 번" 규칙을 가져온다. 고른 기간의 목표가 상위 목표를 가지면 그 상위 제목 아래로 모으고(묶음 제목에 상위의 숫자도 회색으로), 상위가 없는 목표는 "상위 없음" 묶음. 1단계 행 아래에 하위 목표와 연결된 할 일을 들여써서 한 번만 보인다. 편집은 오른쪽 패널(자동 저장, 새 목표는 '추가'를 눌러야 생김 — 할 일 편집 패널과 같은 규칙). 진행 막대는 회색(`--text-2` on `--track`). 합산 방식 설명은 편집 패널에만 둔다.

## 기록

**지금 문제**

| 문제 | 원인 |
|---|---|
| 30행 중 대부분이 `— — —` | 기록 없는 날도 한 행씩. 신호 대 잡음비가 낮다 |
| 숫자 열이 훑어지지 않는다 | 비례폭 글꼴, 왼쪽 정렬, `계획 / 실제` 한 칸에 두 값 |
| 좁은 창에서 표가 넘친다 | 5열 표 + 오른쪽 상세가 나란히, 열 우선순위 없음 |
| 오른쪽 상세 위치를 `padding-top: 68px`로 맞춤 | 구조 대신 숫자로 정렬 |
| 상세에 위계가 없다 | 그날 요약 숫자 없이 할 일 목록부터, `· 완료`를 제목에 붙임 |

**1초 질문:** 최근 며칠 얼마나 했나(집중·완료), 계획보다 길었나 짧았나? 그날 무엇을 했나?

**자체 설계:** 표 대신 날짜 목록. 주 단위로 묶고 묶음 제목에 그 주 합계(집중 · 완료). 날짜 행 = 날짜(고정폭) | 집중 시간 + 짧은 회색 막대(30일 중 최대 대비 길이) | 완료 n / m | 계획 대비 ±. 열은 고정 폭 격자, 숫자 오른쪽 정렬, 줄바꿈 금지. 연속으로 기록이 없는 날은 "11/8 – 11/18 · 기록 없음" 한 줄로 접는다. 오른쪽 열은 고른 날짜: 요약 카드(큰 집중 시간, 완료, 계획 대비) → 할 일 목록(완료는 회색 체크) → 집중 세션 → "이 날짜 열기". 로그 폴더는 제목 옆 보조 버튼.

**비교**

| 기준 | 자체 설계 (주 묶음 날짜 목록) | 표 유지 + 숫자 정렬만 개선 |
|---|---|---|
| 정확성 | 같은 값, 빈 날 접힘으로 의미 있는 날이 위로 | 같은 값, 빈 날 그대로 |
| 훑기 | 막대 길이로 많이 한 날이 먼저 보임 | 숫자를 읽어야 |
| 좁은 창 | 열 우선순위(계획 대비 → 완료 순으로 숨김) | 가로 스크롤 |
| 단순함 | 행 모양이 '오늘' 목록과 같다 | 표 고유 스타일 유지 |

**결정:** 자체 설계 + Primer/EUI 숫자 규칙(오른쪽 정렬, tabular-nums, 줄바꿈 금지) + Carbon 행 높이 40. 막대는 집중 시간 하나에만(같은 정보를 숫자·막대·퍼센트로 세 번 보이지 않게 — 원칙 ④), 회색. 계획 대비는 `계획 대비 +12분` / `−8분` 사실만, 색 없음(원칙 ⑥). 창이 좁으면 계획 대비 열 → 완료 열 순으로 접고, 그 값은 오른쪽 상세에 있다. 오늘 행에는 "오늘" 표시, 오늘 행의 집중 시간은 세션이 끝날 때 갱신된다(흐르는 중인 시간은 '오늘' 화면 몫).

## 설정

**지금 문제**

| 문제 | 원인 |
|---|---|
| 정렬이 두 가지 | 토글은 한 줄(라벨 왼쪽·스위치 오른쪽), 선택 상자는 라벨 위 + 640px 전체 폭 |
| 슬라이더가 무겁다 | 브라우저 기본 range를 `accent-color`로 칠해 굵고 진한 막대, 값은 멀리 오른쪽 |
| 구석 버튼 네 개가 한 줄로 길다 | 테두리 버튼 4개 + 초기화 |
| 묶음이 약하다 | 회색 소제목 하나로만 구분, 오버레이 항목 8개가 한 덩어리 |

**1초 질문:** 그 설정이 어디 있고 지금 값이 뭔가?

**자체 설계:** 모든 항목을 같은 행 모양으로: 왼쪽 라벨 + 회색 설명 한 줄, 오른쪽 조작. 행 높이 최소 48, 묶음은 `.card` 하나. 선택 상자는 내용 폭(최대 240)으로 오른쪽. 슬라이더는 얇은 트랙(4px)과 작은 손잡이, 값은 슬라이더 왼쪽에 고정폭 숫자. 구석은 작은 화면 그림(2×2 목표 영역)으로 한 칸에. 오버레이는 "표시"와 "위치·조작" 두 카드.
